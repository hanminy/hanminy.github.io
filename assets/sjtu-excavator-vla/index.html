4. 모델은 숫자의 의미를 모른다

영상·지시문·숫자열 → 숫자열을 내는 함수

SmolVLA가 받는 형식

  • 카메라 개수 자유 · 내부에서 512×512로 패딩
  • 상태·행동은 최대 32차원 · 모자라면 0으로 채움
  • 평균·표준편차로 정규화된 숫자열로만 봄

그래서 생기는 일

  • 붐·버킷을 따로 “지원”하지 않음 · 4개짜리 숫자일 뿐
  • 사전학습은 소형 로봇팔 · 주로 관절 위치 목표
  • rad/s 속도 출력은 팀의 선택 · 행동 의미가 바뀜
  • 사전학습 그대로는 굴착에 못 씀 (팀 기록)

7. LoRA: 원래 W는 두고 작은 보정만

각 층 안쪽에 가늘고 긴 행렬 두 개를 나란히 붙인다
  • A가 줄이고 B가 늘림 · A·B만 학습
  • 100만 개 대신 약 1.6만 개
  • B = 0으로 시작 → 처음엔 원래 모델과 동일
  • 학습 후 BA를 W에 합치면 속도 그대로
  • 가정: 큰 W의 일반 지식은 대체로 맞다

12. 정책이 실제로 한 것

순수 엔드투엔드가 아닌 상태기계 + VLA 하이브리드

정책이 한 것

  • 주어진 좌표로 버킷 접근
  • 하강 중 스윙·암, 버킷(×0.5)
  • 컬 중 암
  • 버킷 닫기·선회 시작으로 단계 전환을 앞당김

정책이 안 한 것

  • 어디를 팔지 선택 · 좌표가 상태로 주어짐
  • 적재 확인 · 전환은 버킷 각도만
  • 들기 · 선회 · 덤프
  • 새 장면 · 여러 번 연속 굴착
저자 스스로 “정책 단독이 아닌 시스템 성능”이라고 밝힘 · 후속 팀: 감독기 없이 무작위 500장면 290 성공(입자 ≥ 100, 다른 체크포인트) — 같은 선 비교 불가
